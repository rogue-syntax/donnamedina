## Readout (2026-11-14)
- The CONTROL slots show the parameter being turned **or under the mouse**: readable name on the first line, value with units on the second (`NVGView::drawCtrlValueOutput`, positions from `editorLayout::column::kReadout`).
- Names and values come from `source/paramDisplay.{h,cpp}` (no SDK dependency). `NVGView::paramName/envName` return `paramDisplay::label(pid)` when there is one, else the old identifier. `DX10Controller::readoutValue(pid, normalized)` builds the context (the stepped value the engine gets, from the parameter's own string like `changeVertSwitch`; the paired `*_ENV_SRC`; the LFO's BPM toggle) and calls `paramDisplay::value`. The controller readout handlers (`onEnv`, `onEnvBipolar`, `onPanEnv`, `onEnvLev`, `onTuneSwitch`) pass that string instead of the raw normalized number.
- Units follow what the engine does with the value (checked against the code, not by ear):
  - TUNE / MOD TUNE: frequency ratio `f * 2 * v` (x0 .. x1 .. x2, i.e. down to 0 Hz and up one octave), shown as ratio and semitones. The `* 72` semitone formula in `recalcTune` only feeds `carPitchMultiplier`, which no voice reads.
  - FINE: `tuneC += (v - 0.5) / 100`, about ±17 cents at centre tune.
  - OCT: step - 3, clamped by the engine to -2..+2 (list "1".."5"). MOD OCT: step - 6 (list "1".."12" -> -5..+6). INTERVAL / MOD INTERVAL: +1..+12 semitones (lists start at "1"; no unison position). MOD BEAT: step/4 cycles per beat of detune.
  - CUTOFF: the engine's log scale (`DXGenerator` `filterLogScale2`: 80 Hz .. 1.8 kHz at 0.5 .. 18 kHz). The controller's own scale differs (B-57). RESONANCE: Q 0.50 .. 4.58 (B-41).
  - Env amounts: ±100 % plus the source name; for stepped targets also the range at full source (`amount * 13` semitones etc., truncated as the engine does).
  - Envelope attack/decay/release: time to cover 95 % (3 time constants of the one-pole curves `exp(k*v - k)` s, k = 8/6/5); decay above 0.991 = HOLD. LFO rate: 0.08..20 Hz, or the tempo division when BPM sync is on (`quants[]`: 1/1, 1/2., 1/2, 1/4., 1/4, 1/8, 1/8T, 1/16, 1/16T, 1/32, 1/64). LFO fade-in: 0.03..1 s, OFF below. LFO phase: ±180 deg (bipolar; the per-wave meaning in `recalcLfoNPhase` was not checked).
  - GAIN: % and dB. PAN: L/R 0..100, CENTER.
- Hover: `NVGView` is an `IMouseObserver` of the frame (registered in `attached`, removed in `removed`). `onMouseEntered` takes the control's tag and calls `BaseController::showParamReadout(pid)`; `DX10Controller` runs the handler only if it is one of the display-only readout handlers (or shows ON/OFF for a toggle), so hovering a reset/step button or the step target does nothing. While hovered, `RandyTxt::hold` stops the fade; it fades when the mouse leaves.
- `RandyTxt::reset` rewritten (B-58): a different control always scrambles in; the same control updates in place and stays up while it changes. The readout is cleared after the editor-open catch-up (first frame), so it does not flash the last parameter of that burst.
- Test: `READOUT_TABLE=1 bin\editor_cycle_test.exe` prints the readout for a set of params at 0/0.25/0.5/0.75/1. `EDITOR_SHOT_HOVER=<pid>` with `EDITOR_SHOT` sends a mouse move onto that control before the capture (through the real frame/observer path) and prints the readout state. Keep the real mouse outside the top-left 1250x580 px while it runs: real moves over the topmost test window end the synthetic hover.

## Scope (2026-11-14)
- Capture: `source/scopeCapture.h` (`ScopeCapture`, no SDK dependency). `DX10Processor::doProcessing` pushes the mono sum of the final output (after the master volume) while `BaseProcessor::scopeEnabled` is set. It triggers on a rising zero crossing (hysteresis 1e-4; untriggered after 2048 points without one, e.g. silence or very low notes) and records 1024 points: 23.2 ms at 44.1 kHz, 21.3 ms at 48/96 kHz (every n-th sample at 88.2 kHz and up). Frames go through a lock-free triple buffer, so the audio thread never waits, allocates or sends.
- Transport: `BaseProcessor::onTimer` (15 ms, main thread) sends each new frame as `PMSG_SCOPE_CHAR` with a binary attribute; repeated silent frames are not resent. Capture and sending only run while an editor is open (`CMSG_SCOPE_ENABLE_CHAR` from `NVGView::attached/removed`).
- Display: `BaseController::notify` copies the frame into `scopeFrame[]` (`scopeFrames` counts them); `NVGView::drawScope` (from `drawRightColumn`) draws a grid (8 time divisions, centre and +-0.5 lines) and the waveform at fixed scale (+-1 = full height, clipped), with a wide low-alpha stroke under a thin bright one.
- Tests: `tests/note_off` "Scope capture" (trigger, silence, 96 kHz, frame identical to the processor's output, timer-only messages, controller receive). `EDITOR_SHOT_SCOPE=1` with `EDITOR_SHOT` hands the controller a test frame before the capture (the editor test has no processor).

## Voices in the scope (2026-11-14)
- `BaseProcessor::updateVoiceStates` (audio thread, after each chunk in `DX10Processor::doProcessing`, only while an editor is open) writes one byte per pitch into `std::atomic<uint8> voiceStates[128]`: `voiceStateByte(held, level)` in constants.h, bit 7 = key held (`RVoice::noteActive`), bits 0..6 = amp-envelope level (`voiceEnvLfo[1].cenv`, 0 = silent). Only the voices in the render list (`DXGenerator::notes`) are read.
- `BaseProcessor::sendVoiceStates` (timer) sends the 128 bytes as `PMSG_VOICES_CHAR` when they changed; the controller copies them into `BaseController::voiceStates`.
- Drawn behind the scope's waveform by `NVGView::drawScopeVoices` (called from `drawScope`). Step 4 first had them as a 128-column strip in their own band; that band was merged into the scope, which is now 28 px taller (the master row moved down by 28 px, uidesc origins and `editorLayout::column` together).
- Zoom: the x range is the lowest..highest sounding pitch, releasing voices included (`paramDisplay::voiceRange`): at least 12 semitones (centred, kept inside 0..127), at most all 128; with nothing sounding the last range stays. The drawn range glides there by time (`voiceViewLo/Hi`): widening with a 60 ms time constant, so a new outer note appears at once, narrowing with 250 ms.
- Drawing: black-key slots darker when a slot is at least 3 px; a line at every C, labelled (MIDI 60 = C4) when an octave is at least 30 px wide; each sounding pitch is a bar 72 % of its slot (at least 1.5 px), height and brightness from the level (square-root curve so quiet voices stay visible), vertical gradient and a bright cap, magenta while held, cyan while releasing.
- Tests: `tests/note_off` "Voice strip" (held chord, released note, timer-only messages, encoding, controller receive, `voiceRange` cases); `EDITOR_SHOT_SCOPE=1` also hands the controller a spread chord, `=2` a single note.

## Preset bar (2026-11-14)
- Bar: `<` previous, the preset name (`*` after any edit since it was loaded; a caret marks the menu), `>` next, SAVE, RND. Drawn by `NVGView::drawPresetBar`; the mouse goes to `PresetBarView` (presetBarView.h), an invisible custom view `presetBar` in vstgui.uidesc (937,80 294x22, in the controls template, created by `BaseController::createCustomView`). It writes the hovered zone to `BaseController::presetHover` and calls `onPresetBarClick`; NVGView sets `presetBarEnabled` false while the about window is open.
- List: the 7 factory presets, then every `*.vstpreset` under `Documents\VST3 Presets\Rogue Syntax\Donna Medina` (subfolders included, sorted by name), rescanned on each click. `<`/`>` step through it and wrap. The name opens a menu: FACTORY, USER, "Randomize all", "Save as...", "Open file...", "Show preset folder".
- Loading, factory or file, goes through the plugin state like a host's preset load (`DX10Controller::applyPresetState`, mdaDX10Presets.cpp): the state blob (`presetTools::State`) goes to the processor (`CMSG_SET_STATE_CHAR`, `setState`) and to the controller (`setComponentState`), then `restartComponent(kParamValuesChanged)`. Master volume and bypass are global: the current ones replace those in the blob. Factory presets are built from `DX10Processor::programParams`; a file must have the processor's class ID.
- SAVE (and "Save as..."): a save dialog (`CNewFileSelector`) in the preset folder, then the controller asks the processor for its state (`CMSG_GET_STATE_CHAR` -> `PMSG_STATE_CHAR`) and writes it with `PresetFile::savePreset` (component state only; hosts load these files too).
- RND: asks for the state, then `presetTools::randomize`. Click = variation: continuous parameters the rules allow move by at most their nudge (0.03..0.1), switches and modulator ratios stay, unused modulation amounts stay unused, values never leave their safe range. "Randomize all" = full: every allowed parameter random within its range, 65 % of the modulation amounts at none, modulator tune from the ratios x0.5/x1/x1.5/x2. Kept by both: carrier TUNE/FINE/OCT/INT and their env amounts, MOD_BEAT, AUX, link toggles, env delays, STEP_CTRL_TARG, MASTER_VOL, buttons. Safe ranges: GAIN 0.55..0.9, FILTER 0.45..1, Q 0..0.6, PAN 0.35..0.65, MOD_GAIN 0..0.8, amp env (ENV 1) attack 0..0.45, decay 0.8..1 (lower decays to silence within ~0.15 s), release 0.1..0.6.
- Tests: `tests/note_off` "Preset bar": state round trip, the processor's get/set-state messages, factory and file loads (volume kept), controller state, variation and full-random limits, and 24 full-random patches rendered with a chord must all sound (no NaN, peak <= 4); `DM_RND_DIAG=1` lists, for any silent one, which single parameter brings it back. `tests/editor_cycle` "B-59" (see BUGS.md).

## Scope info: voice count and output peak (2026-11-14)
- Top left of the scope: `VOICES n/32  HELD h` (`paramDisplay::countVoices` over `BaseController::voiceStates`; 32 = `POLY_LIMIT` in constants.h, which `DXGenerator::POLYCOUNT` now starts from). Top right: `PEAK x.x dB` in dBFS (`paramDisplay::peakText`), amber from -1 dB, and a red `CLIP` tag for 2 s after any message at or above 0 dBFS (a NaN in the output counts as a clip). Both sit on dark plates over the waveform (`NVGView::drawScopeInfo`, drawn last by `drawScope`; the waveform itself moved to `drawScopeWave`).
- Peak path: `DX10Processor::doProcessing` takes max(|l|, |r|) per sample while an editor is open and folds the chunk's value into `BaseProcessor::outPeak` (`notePeak`, atomic max). `sendPeak` (timer) exchanges it with 0 and sends `PMSG_PEAK_CHAR`; the controller keeps `outPeak` and counts `peakFrames`. The view holds the largest value for 1.5 s, then follows.
- Tests: `tests/note_off` "Scope info" (sent peak equals the rendered output's peak, timer-only messages, one 0 per silence, controller receive, `countVoices`, `peakText`); `EDITOR_SHOT_SCOPE=1` adds a -4.6 dB peak, `=2` a +1.2 dB over (CLIP).

## Creation chain
`DX10Controller::createView` -> `RSView` (VST3Editor subclass, uidesc `vstgui.uidesc`) -> uidesc asks for sub-controller `nvgViewController` -> `DX10Controller::createSubController` (`mdaDX10Controller.cpp:79`) does `new NVGViewController(editor, this)`, whose ctor does `new NVGView(CRect(0,0,kEditorWidth,kEditorHeight), controller)`. `NVGViewController::createView` returns that `nvgView` when the uidesc view has `custom-view-name="nvgView"`. So **one new NVGView per editor open**.

## NVGView
- `NVGView : COpenGLView` draws the whole UI with NanoVG into one GL view (1248x542 since 2026-11-13, see Layout below). The normal VSTGUI controls (modded `CBKnob`, `CBButton`, `CBSlider`, `CBVerticalSwitch`, `CBStepCtrlButton`) still exist as hidden/transparent input handlers; their look is drawn by NanoVG.
- `attached()` (`NVGView.cpp:934`): create GL3 NanoVG context + font; walk **all views in the frame** (`getFrame()->getViewsAll`, an SDK mod), and for each one whose `customRSType > -1` call a `setupX` function by type number: 1 knob, 2 button, 3/10 slider, 4 vertical switch, 5 vertical slider, 6 osc-symbol (name decides sine/saw/tri/square), 7 knob2 (via setupRKnob), 8 image, 9 click button, 11 step-ctrl button, 12 knob2, 13 more-info, 14 close-window button. Each `setup` builds an `RSBView` data record, stores it in `RViewsMap`, indexes it by control tag in `viewIndex[tag]`, and registers a draw handler in `RDrawVector[layer]` (the `Draw`/`REvent` data+binder system).
- `drawOpenGL()` (`:1391`) every frame: `onNVGViewReady()` flush, animations, draw envelopes/LFOs, then each registered draw handler, then overlays; `glFinish(); invalid();` (continuous redraw).
- `removed()` (`:1137`): clears flag, makes the GL context current and deletes `vg` (B-28 fix; `nvgDeleteGL3` now also frees the font stash again, B-54), `views` cleared. VSTGUI then frees the `NVGView` and deletes the `NVGViewController`, which clears `DX10Controller::nvgViewController` (B-29). Measured with `tests/editor_cycle`.
- Event/data system `revent/`: custom `Map.h` hash (ska) of name -> data + member-function binders. Older `removedFromSrc/REvent*.{h,cpp}` is the earlier version. Notes at `C:\vst3sdk\revents.txt`.

## Pass 4b: handlers, text effect, knob drawing (read)
- `onEnv/onEnvBipolar/onPanEnv/onEnvLev/onTuneSwitch/onOnOffBtn/onEnvSrc/onChangeOSCType/onChangeLFOOSCType/onChangeModType` (`NVGView.cpp:52-268`) only update the on-screen readout: `targDisplayTxt` (parameter name) and `targValueTxt` (value text) via `RandyTxt::reset`. `onChangeModType(3)` also sets `beatModOn`, which drives the beat-mod indicator. They never touch audio params.
- `onResetButton` (`:271`): `idx = pid - WIDTH_RESET` indexes `resetSwitch[7] = {WIDTH_, TUNE_, FINE_, MOD_GAIN_, MOD_WIDTH_, MOD_TUNE_, MOD_FINE_}` (reset pids 150..156); sets the target control to 0.5 normalised and calls its `valueChanged()`, plus a blink animation. So a "reset" is just the GUI control being set to centre, which then goes through the normal parameter path.
- `onStepCtrlSwitch`/`onStepCtrlButton`/`onToggleButton`: set blink/glow animation entries in `animationReel` (+ `stepCtrlSelectAnim`).
- Animations are plain structs (`Anima`: name, control index, state) in `animationReel`; `drawOpenGL` runs each through `nvgAnimations[name]` (member-function table: `buttonBlink`, `buttonBlinkFastest`, `buttonGlow`, `stepTargBlink`) until it returns state 1. The VSTGUI `animationTick/Start/Finished` overrides are marked "NOT USED".
- `RandyTxt`: the scrambling-letters readout. `randyCharSrc` is 32 characters, matching `rand() % 32`. Per-frame timers (B-35).
- `drawKnob`: not an image knob; draws a circle outline, a magenta fill whose alpha = `alpha * blinkIntensity`, and a line from centre to `cBKnob->valueToPoint`. **The pointer is drawn from the VSTGUI control's own value each frame**, so the display only ever shows the control's state; it is correct only if `setViewsFromBase`/`doFromBase` kept the controls in sync (links to B-02).

## Pass 4c: draw functions and revent (read)
- `drawEnv1-3`: envelope shape polygon from the attack/decay/release knob positions and the decay-toggle button (approximation of the sound, not the real coefficients). `drawEnv4-6`: LFO preview from type/amp knobs, a phase slider, and the rate value pushed from the processor (`lfoNRate` pointers into the controller, via `PMSG_LFO4/5/6_RATE`); number of cycles drawn tracks rate. Names are hard-coded (B-38).
- `drawSlider/SliderVert`: bipolar fill from centre by `value - 0.5`. `drawSwitchVert`: one tick per step (`getMax()+1`) and a magenta marker at the current value. `drawSelctedStepTarg`: outline round-rect (RSBType 1) or circle (2) around the step-control target; dereferences `selectedStepTarg` unguarded (set in `attached`).
- **revent** (`REvents.h`): a registry class owning (a) events + binders (queue and `execQueue`; apparently unused by the GUI), (b) `RDataMap` name->`RData` and `boundHandlers` handle->`{dataName, member fn}`, run by `execDataHandler(handle)` each frame, (c) `functionMap` name->member fn, run by `callFunction`; this is how `attached()` dispatches `setupRKnob` etc. by string name, (d) a voice binder set for a former RVoice-event design (commented out in the newest copy). Pointer-to-member of `RDataConsumer` bound to the `NVGView` instance. Hash map = ska (`Map.h`, `ska.h`).
